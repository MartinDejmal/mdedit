Getting started

mdedit is a desktop WYSIWYG Markdown editor for Windows, macOS and Linux. See formatting as you type. Documents stay on your disk; no account or cloud service is required.

This guide describes the current development branch. A published installer may contain an older feature set. Find your exact application version under Help → About.

Choose an installer for your OS and CPU: Windows x64 (EXE/MSI), macOS Intel or Apple Silicon (DMG), Linux x64 or ARM64 (AppImage/DEB/RPM). Mark an AppImage as executable. Unsigned Windows installers and ad-hoc signed, non-notarized macOS packages may trigger system warnings; install only trusted releases.

The Windows desktop uses the WebView2 Runtime. The built-in help and Mermaid previews do not require internet access.

Workspace and help

The main menu contains File, Edit, View and Help. The toolbar sits underneath. Toggle file browser is its first button. If the window is too narrow, » / More editor tools on the right opens the remaining controls. An action, outside click or Escape closes the popup.

The left side can contain Files, then the heading Outline, followed by the editor. Toggle Outline from View, click a heading to navigate, or drag its right edge to resize it; the width is remembered. The status bar shows the file path, Saved / Modified, and external-change warnings.

Help → Help or F1 opens this offline guide. Čeština / English switches the language of Help and About, not the entire editor interface. Use Close/Zavřít or Escape to dismiss it. Your document remains unchanged. Native File/Edit/View menus are temporarily disabled while this dialog is open; close help to resume editing. Closing the main window dismisses help and still protects unsaved changes with a confirmation dialog.

Zoom: choose 50–200% in the toolbar selector, or use Ctrl + mouse wheel over the editor (up zooms in, down zooms out). Zoom uses Control on macOS too. If the selector does not fit on the toolbar, find it under ».

Zoom changes only the editor view, not the toolbar, Files or Outline, Markdown content, Saved/Modified state, Undo history or HTML/PDF exports. It survives switching and creating documents for the current application session, and always starts at 100% in a new session. It is never stored in settings or document files.

Opening, creating and saving documents

  • File → Open… opens .md, .markdown and .txt files. You can also pass a file path at launch, use your OS “Open with” action, or drag a file from the OS onto the application window.
  • File → New: with Files visible and a folder selected, creates an empty Untitled.md on disk immediately. If the name exists, it uses Untitled 2.md, and so on. The new file opens as Saved. Without a selected folder, or with Files hidden, New creates an untitled document only in the editor.
  • Save saves the current document, asking for a path when it is untitled. Save As… always asks for a new path. The app does not automatically save every keystroke.
  • Recent Files lists recently opened files. When launched without a file argument, the app attempts to reopen the last document.
  • Reload from disk reads the current file again. Changes made by another application produce a reload warning; unsaved text is not overwritten automatically.

Modified means changes relative to the saved baseline. Merely opening or normalizing Markdown is not a user edit. Undo can return the document to Saved. Undo/Redo history resets when another document is loaded or the file is reloaded.

Unsaved changes and confirmation dialogs

Switching files in Files shows Save changes before switching files? only when the current document has changed. Save saves and continues, Discard drops changes, and Cancel keeps editing. Cancelling Save As or a write failure stops the switch. After a successful switch, the editor scrolls to the start of the new file; cancelling preserves the viewport position in the current document.

New, regular Open, reload and closing the window use Discard unsaved changes? with Discard / Keep Editing. To preserve changes, select Keep Editing, save, and repeat the action. The window close button respects this protection.

Deleting the open file through Files is a separate operation: it deletes the disk file and, when the document is modified, also warns that unsaved edits will be lost.

File browser: folders and file operations

Open Files using the first toolbar button or View → Toggle file browser. If a saved file is open, the browser starts in its directory. Otherwise choose a folder using Open folder / Choose folder. The tree displays subfolders and only .md files, including .MD. Open .markdown and .txt through File → Open; they do not appear in the tree. Symbolic links are not displayed.

  • Click a folder to select it and expand/collapse it. Click the root row to select the root. The selected directory is the destination for New and New folder.
  • Parent folder moves the entire tree one directory up; it is disabled at a drive/share root. Refresh folder reloads the tree.
  • New folder asks for a name and creates a directory inside the selected folder. Existing destinations are never replaced.
  • Click a file to open it. Click an already selected row, or press F2, to rename it. Names must end in .md and cannot contain path separators or reserved characters.
  • Move a file by dragging it onto a folder or the root row. The destination folder expands after the move. An existing file with the same name causes an error instead of being overwritten.
  • Right-click a file for Open, Rename…, Move to folder…, Delete…. Move to folder opens a destination picker. A folder context menu can open that folder as the tree root or create a new folder.
  • Delete or Delete… requires confirmation. Deletion is permanent; the app does not use the recycle bin. Confirming deletion of the open document opens an empty untitled document.

Moving or renaming the open file preserves its unsaved content and Modified state, and updates the path used by Save. These operations apply to files; renaming, moving or recursively deleting entire directories is not currently part of the UI.

Formatting, lists and tables

  • The toolbar provides bold, italic, headings, bullet/ordered/task lists, tables, links, images and code blocks. Undo / Redo availability follows the edit history.
  • The heading button cycles normal text → H1 → H2 → H3 → normal text. In a list item it first removes that item's list wrapping, preserving surrounding items and inline formatting. One Undo restores the conversion.
  • Tab / Shift+Tab indents/outdents the nearest list item, including task and mixed lists. A first item without a preceding sibling cannot nest: Tab leaves it unchanged and keeps focus in the editor. Shift+Tab at the outermost level can turn an item into a paragraph.
  • Task list creates a task list at the cursor, or converts selected nonempty lines into tasks. A checkbox changes a task's checked state.
  • Insert table with no selection inserts a 3×3 table with A/B/C headers. With selected text it creates a row per paragraph or hard break. Tabs separate columns; conventional Markdown tables with leading/trailing pipes are also supported, excluding the header separator row from data. The first row becomes the header and shorter rows receive empty cells. Inline formatting and text outside the selection are preserved.
  • Insert link applies a URL to selected text, or inserts the URL when the selection is empty. Remove link removes it. Insert image from URL asks for an image URL and optional alternative text; local attachment management is not currently provided.

Code and Mermaid

Enable Code block and choose a language in the Code selector. Options include plaintext, Mermaid, JavaScript, TypeScript, JSON, HTML, CSS, Bash, SQL, YAML and Markdown.

Choose mermaid for diagrams. The preview below the source updates as you edit and displays an error for invalid syntax. Mermaid is bundled and needs no CDN. For example, flowchart LR followed on the next line by A[Start] --> B[End] creates a simple diagram.

HTML and PDF export

Use File → Export as HTML… / Export as PDF… or the toolbar icons to export the current editor content, including unsaved edits. A filename is suggested from the document and you choose the destination in a dialog. Export does not mark the source Markdown as saved.

PDF includes selectable text, bundled serif/monospace fonts with diacritics, syntax highlighting, lists, checkboxes, blocks inside tables, images and vector Mermaid diagrams. Long documents paginate; line wrapping need not be pixel-identical to the editor's viewport.

Remote images must be available and permit CORS for embedding in PDF. An unavailable image stops export with an error instead of silently omitting content. HTML export is a standalone styled document; its Mermaid preview currently loads a library from a CDN and requires internet access. This differs from the offline editor preview and PDF export.

Limitations and troubleshooting

  • Markdown ↔ HTML conversion is not lossless for every construct. Keep a copy of important or unusual documents before editing. The app is not a backup or version-control manager.
  • A failed operation displays a toast or an error in the tree. Check permissions, directory existence, filename collisions and file availability. Use Refresh to reload the tree.
  • For external changes, decide whether to keep your editor content or load the disk version. Confirming Reload can discard unsaved changes.
  • Find missing toolbar controls under ». Temporarily hide Files or Outline from View to gain space.
  • Check Mermaid syntax and the selected language for diagram errors. Check image URLs and CORS for PDF image errors. Export requires an active document.
  • The language switch affects Help and About only. Full editor localization and dark mode are not currently implemented.
